# pid-gimbal-tuning

PID 调参方法论 skill —— 云台 / 舵机 / 小车 / 无人机通用。核心是把"系统现在什么现象"  
反推成"该改哪个参数、改哪个方向"。

## 安装

把整个 `pid-gimbal-tuning/` 目录放进 skills 目录即可。

**WorkBuddy（Windows）** —— 放到用户级 skill 目录，全局可用：

```
C:\Users\<你的用户名>\.workbuddy\skills\pid-gimbal-tuning\
```

**macOS / Linux**：

```
~/.workbuddy/skills/pid-gimbal-tuning/
```

也可以放项目级目录，只对当前项目生效：

```
<项目根>/.workbuddy/skills/pid-gimbal-tuning/
```

放好后重新开启一次对话即可生效。没有任何第三方依赖，Markdown + 纯标准库 Python。

## 怎么用

### 方式一：直接问（推荐）

不需要记任何命令，用日常说法就会自动命中：

> 云台抖得厉害怎么调  
> PID 参数怎么整定  
> 低频晃动是怎么回事  
> 舵机滋滋响

### 方式二：拿波形判读

如果你用 VOFA+ 抓了串口数据，可以让脚本直接给结论：

```bash
python scripts/analyze_waveform.py 数据.csv --fs 100
```

输出示例：

```
主导现象     : 低频漂移/来回晃（主频 0.75 Hz，周期约 1.3 s）→ KI 过大
振荡幅度     : ±17.72
积分项: 首=0 末=87.6 → 持续增大，需警惕积分饱和

调参建议
  · 表2 第2行：减小 KI
  · 低频抖动优先减 KI，不要先去动 KP/KD
```

| 参数                              | 说明                                 |
| ------------------------------- | ---------------------------------- |
| `--target-col` / `--actual-col` | 显式指定目标列、实际值列。列名认不出来时必须给            |
| `--integral-col`                | 积分项列。**强烈建议提供**，见下                 |
| `--fs`                          | 控制频率（Hz），默认 30。多数云台串口控制在 30~100 Hz |
| `--window`                      | 稳态分析段长度（秒），默认 2                    |

CSV 要求：带表头（VOFA+ 的 DataLoader 直接导出即可），至少含"目标"和"实际值"两列。  
列名自动识别 `target`/`目标`、`opencv`/`actual`/`实际`/`当前` 等关键词。  
无表头也能跑，脚本会按数据形态推断并打印提示，但正式分析建议显式指定列名。

### 先跑一遍回归，确认环境正常

```bash
cd scripts
for f in w_jitter w_drift w_static w_slow w_overshoot; do
  printf "%-14s" $f
  python analyze_waveform.py samples/$f.csv --fs 100 | sed -n '8p'
done
```

期望输出（每行都是"某现象 → 某参数"）：

```
w_jitter      主导现象     : 高频颤动（主频 32.1 Hz）→ KD 相对 KP 过大
w_drift       主导现象     : 低频漂移/来回晃（主频 0.75 Hz，周期约 1.3 s）→ KI 过大
w_static      主导现象     : 存在静差（最终只走到目标的 80%）
w_slow        主导现象     : 响应迟缓（上升时间 5.77 s）→ KP 太小
w_overshoot   主导现象     : 超调振荡（超调量 +52%）→ KP 过大或 KD 不足
```

只需要标准库，`python3` 即可。Windows 上如果 `python` 不通，用 `py`。

## 方法论速览

**铁律：每次只改变一个参数，从影响最直接的那个开始降。**  
同时改两个参数等于同时抛两个未知数，现象变了你也不知道是谁的功劳。

| 现象                  | 动作         |
| ------------------- | ---------- |
| 抖得**快**（高频、滋滋声）     | 减 KD       |
| 晃得**慢**（1–2 秒周期来回漂） | 减 KI       |
| 追不上、反应慢             | 加 KP       |
| 冲过头反复过冲             | 加 KP 或加 KD |
| 到不了位、有固定偏差          | 加 KI       |

一句话分工：**KP 决定响应速度，KD 决定刹得住不住，KI 决定能不能压到零。**

完整流程（KP 起步判极性 → 加 KD 找"反应快但基本不抖" → 有静差才加 KI）、  
加 KI 的五步走、常见坑清单、以及可直接套用的 STM32 C 实现，都写在 `SKILL.md` 里。

## 调 KI 时记得打印积分项

波形形状会骗人 —— 不同的参数组合能画出相似的形状。但积分项的走势不会，  
它是不是在持续累积，是判断该加 KI 还是减 KI 最直接的依据。

```c
printf("%f,%f,%f\r\n", target_x, opencv_x, X_integral);
```

## 前提

PID 能调好的前提是**先做死区判断、积分限幅、输出限幅**。这三样没做，调参一定会翻车  
（积分饱和后重新追上会猛冲，舵机打到物理极限会卡死结构）。具体做法见 `SKILL.md`。

另外，调参前请确认机械重心已调平。重心没调平时电机要持续输出力矩维持姿态，  
再怎么调 PID 都是在跟偏载较劲。
