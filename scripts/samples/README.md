# 测试样例

`samples/` 下是 6 个合成波形，用于回归验证 `analyze_waveform.py` 的判定逻辑。
全部按 fs=100 Hz、800 点（8 秒）生成，第 1.0 秒处目标从 0 阶跃到 100。

| 文件 | 构造的波形 | 期望判定 |
|---|---|---|
| `w_jitter.csv` | 12 Hz 高频颤动叠加在快速上升沿上 | 高频颤动 → KD 相对 KP 过大 |
| `w_drift.csv` | 0.5 Hz（2 秒周期）大幅低频往复 | 低频漂移 → KI 过大 |
| `w_static.csv` | 最终只走到 80（纯静差，无振荡） | 存在静差 → 加 KI |
| `w_slow.csv` | 时间常数很大的极慢上升，7 秒才到 94% | 响应迟缓 → KP 太小 |
| `w_overshoot.csv` | 欠阻尼二阶系统，超调 +52% | 超调振荡 → KP 过大或 KD 不足 |
| `noheader.csv` | 同 w_jitter，但**无表头**，且多一列积分项 | 验证列推断：应认出 col0=目标 col1=实际 |

## 跑回归

```bash
cd scripts
for f in w_jitter w_drift w_static w_slow w_overshoot; do
  printf "%-14s" $f
  python analyze_waveform.py samples/$f.csv --fs 100 | sed -n '8p'
done

# 无表头文件应先打印列推断提示
python analyze_waveform.py samples/noheader.csv --fs 100 | head -2
```

## 开发过程中被这套样例抓出来的错误（留着当提醒）

1. **零穿越法测主频严重偏低** —— 12 Hz 实测成 6.2 Hz。改成 DFT 全频扫描 + 抛物线插值细化。
2. **上升时间换算公式写错** —— 写成 `rise_idx / len(seg) * fs`，正确是 `rise_idx / fs`。导致 0.12 s 报成 68 s。
3. **阶跃检测用错了序列** —— 在误差序列上找阶跃，误差里的振荡每半周被误判为阶跃，稳态分析段被挤到数据末尾。加了"必须在目标序列上检测"的注释。
4. **分析窗口太短** —— 固定 2 秒窗口看不到超调峰值和慢上升终点，+52% 的超调被测成 -2.7%。改成从阶跃点分析到数据末尾。
5. **判定顺序错误** —— 静差/迟缓分支抢在超调前面，导致超调波形被判成"响应迟缓"。改成按因果优先级：先判振荡类，再判静态偏差。
6. **无积分列时变量未定义** —— `integral_growing` 只在 `if icol:` 分支里赋值，缺列时 `UnboundLocalError`。
7. **列推断连错两次** —— 先用"平滑度"选实际值列，把积分列认成了实际值（积分是误差累积，天然更平滑）。改用"方向一致性"：实际值列在阶跃后必须朝目标方向移动。
8. **目标列打分用前后半段均值差** —— 阶跃通常发生在前 1/3 处，两半均值差被压缩（真实目标列只得 0.33 分，低于阈值而漏判）。改成用"首个跳变前后的均值差"。
9. **缺少噪声门槛** —— 已稳定的单调波形也被报出虚假低频主频（0.55 Hz），误判成 KI 过大。加了相对于跳变幅度 2% 的幅度门槛。
